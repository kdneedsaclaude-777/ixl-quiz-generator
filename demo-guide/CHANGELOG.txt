  v1.7.0  ·  2026-05-24  ·  "Lifecycle emails everywhere"
════════════════════════════════════════════════════════════════════════

  ADDED  ───────────────────────────────────────────────────────────────
    • Welcome email on first successful email-verification (organic
      signup path). Once per user, ever.
    • Welcome email on admin-provisioned account creation
      (/admin/users + /admin/students with createLogin) — auto-verified
      accounts get a "your password was set by an admin" framing.
    • Tutor-assignment emails — when an admin links a tutor to a
      student, both the tutor ("you've been assigned X") and the
      parent ("X now has a tutor") get notified.
    • Account-suspended security notice — sent to the affected user
      (not dedup'd; security alerts must always fire).
    • Account-reinstated notice when unsuspended.
    • Bulk-suspend emails each newly-suspended user individually.
    • Password-changed security notice — fires even on self-initiated
      password changes so a stolen session gets flagged.
    • Email-change security notice sent to the OLD email address (the
      only one the rightful owner still controls if the email was
      hijacked). The new address still gets its verification link.
    • Tutor weekly digest mirrors the parent digest — cohort summary
      every 7 days, deduped via isoWeekKey().

  NOTES  ───────────────────────────────────────────────────────────────
    • Every new email is best-effort: a send failure logs and returns
      silently, never breaks the mutation that triggered it.
    • Every email honors the platform-wide `email_notifications`
      feature flag in /admin/settings.
    • Welcomes + tutor-assignment emails dedupe via NotificationLog.
      Security notices (suspend, password, email change) intentionally
      DO NOT dedupe.

  v1.6.0  ·  2026-05-24  ·  "Drill-down everywhere + skill authoring"
════════════════════════════════════════════════════════════════════════

  ADDED  ───────────────────────────────────────────────────────────────
    • /admin/quizzes — brand-new drill-down log. One row per quiz, NOT
      averaged. URL-synced filters for grade, student-name search,
      status (completed / active / all), and single-day pin.
    • Clickable chart bars/points — every major chart now navigates to
      /admin/quizzes with filters pre-applied:
          ◇ Admin dashboard: Quizzes-per-day bar  → ?day=YYYY-MM-DD
          ◇ Admin dashboard: Avg-score-per-grade bar → ?gr=N
          ◇ Admin analytics: Quizzes-by-grade bar    → ?gr=N
          ◇ Parent/Tutor: Score-trend point          → quiz results
    • Admin settings: platform stats panel with parent / tutor / admin
      / student / quiz / completed-24h / badge / organization counts.
    • + Add student modal in /admin/students, with optional bundled
      login account (single-step provisioning).
    • + New user modal in /admin/users — creates any role.
    • /admin/content: "+ Add skill" inline button on every expanded
      topic group. Admin types a name; server auto-assigns code
      (e.g. S.12) and number, sets active=true, audit-logs the create.
      New skills flow into generated quizzes immediately.
    • demo-guide/ folder: README + per-role perspective files
      (super-admin, org-admin, parent, tutor, student) + this changelog.

  FIXED  ───────────────────────────────────────────────────────────────
    • /admin/students "View" button now works for admins — middleware
      previously bounced admins off /parent/* paths.
    • /admin/users "All roles" filter now actually shows all roles
      instead of silently falling back to parents.
    • Hydration mismatch on phones with non-en-US locales — every
      Date.toLocaleDateString() now passes "en-US" explicitly.
    • Server SSR / client locale mismatch in Live host console — moved
      window-only URL building into useEffect.

  INFRA  ───────────────────────────────────────────────────────────────
    • LAN-accessible dev: bind dev server to 0.0.0.0 + set NEXTAUTH_URL
      to LAN IP so phones can complete auth callbacks.

────────────────────────────────────────────────────────────────────────
  HOW TO ADD A NEW ENTRY  (for whoever ships the next change)
────────────────────────────────────────────────────────────────────────

  1. Bump the version (semver: MAJOR.MINOR.PATCH).
       MAJOR  → breaking schema or auth change
       MINOR  → new user-visible feature
       PATCH  → bugfix or polish only
  2. Insert a new section at the TOP using the same banner format.
  3. Group lines under ADDED / CHANGED / FIXED / REMOVED / INFRA.
  4. Each bullet stands alone — someone skimming should grok it
     without reading the section above or below.
  5. If a role's feature set changed, also update that role's file
     in this folder (01-…txt through 05-…txt).
